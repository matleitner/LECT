Detailed Description

The following macros are an approximation to implement a Disciplined Exception Mechanism using only the language preprocessor.

Unlike standard try/catch error handling, a Disciplined Exception Mechanism (DbC-DEP) adopts a simpler approach. Under Design by Contract (DbC) principles, a function or method must either succeed by fully meeting its contract or fail completely—no other outcome is acceptable. Therefore, a function only returns if it succeeds. If it fails, it throws an exception. Recovery is only permitted if the function can successfully fulfill its contract on a new attempt, whether by employing a different algorithm or through another suitable method.

This perspective simplifies tremendously error handling solving two very serious problems with common try-catch exception mechanisms:

  • First, there is the possibility of ignoring an error, either by simply omitting the defensive error-handling code or by writing it in a way that ignores the failure (such as catching an exception and doing nothing with it).
  • Second, relying on exception types to differentiate errors overlooks how quickly the meaning of an exception type fades within the function call stack, given that it is typically only meaningful to the direct client. (For a deeper analysis of these issues using Java as an example, see section 4 of Contract-java: Design by contract in Java with safe error handling).

However, in the DbC-DEP a failed function causes the failure of the client function, and so on, until, if required, a rescue is attempted. A rescue never compromises the function/module contract, as it allows only a retry to fulfill the contract (probably by using a different approach, or in a function which prescribes a weaker contract for an alternative acceptable behavior).

Example:

#include <dbc.h>
...
void redundant_function_with_two_alternative_implementations(...)
{
require (..., "..."); // precondition
int algorithm = 1;
rescue_retry;
switch(algorithm)
{
case 1:
...
break;
case 2:
...
break;
}
ensure (..., "..."); // postcondition
rescue_begin
algorithm++;
if (algorithm <= 2)
retry
rescue_end
}

Since exceptions are necessary here, these macros are only applicable in C++ (with EXCEPTION_POLICY macro defined), not in C (for a C approach see c-dbc library).

By default, rescue clause only catches DbC errors (DbC_Error*). This behavior can be modified to catch all types of exceptions be defining the compiling macro CATCH_ALL.
